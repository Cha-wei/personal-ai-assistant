# Project Brief

## 项目身份与目的

- 项目名称：Personal AI Assistant（个人 AI 助手）。
- 目标用户：个人使用者；具体用户画像随真实使用情况逐步完善。
- 项目目标：建立模块化、本地优先的个人 AI 工作空间，整合本地项目与 GitHub 接入、版本变化感知、AI 项目理解、项目全景展示、个人知识库和统一对话入口。
- 近期核心价值：准确接入真实项目来源、识别和解释已观察到的版本变化；在此基础上逐步提供项目理解与可视化，而非先建设完整任务管理或 Agent 平台。
- 本项目自身也是被管理的项目：需求、架构与产品设计属于正式项目工作，确认后的文档与后续代码一样纳入 Git 版本管理。

## 项目阶段与里程碑

- **已完成：Bootstrap（2026-10-26）**。依据 Human 的“个人 AI 助手项目初始化与 GitHub 公开仓库创建”任务，完成独立仓库、通用治理文件、基础文档及首次公开推送。此为历史里程碑，不再作为当前未完成开发范围。
- **当前：产品与总体架构设计**。Human 已确认“架构与产品设计共识 v0.1”及其开发重心调整；本阶段将已确认的设计方向整理进 canonical docs，具体修改仍须经适用的 Git 审核与接受流程。
- **尚未开始：业务功能实施**。当前仓库尚无业务代码，也无可声明通过的软件功能测试。任何模块开发必须由后续任务明确授权。

设计共识、文档合并、业务实现和功能验收分别具有不同含义；Git 提交证明版本，不自动代表设计已获批准或功能已完成。

## 当前已确认的产品与架构方向

- 采用**本地优先的模块化单体**，三个业务模块职责清晰，统一工作空间负责展示与交互。
- **模块 1：项目接入与上下文管理**，独立接入本地目录或 GitHub 仓库，也可关联；按需提供项目结构、文件、Git 事实及版本变化信息。
- **模块 2：智能项目管理**，以项目目标、模块与功能的全景展示和已有开发信息的只读汇总为产品方向；不复制现有 Agent 的任务执行、测试、审核或验收系统。
- **模块 3：个人知识库**，可独立收藏、管理、检索资料并辅助总结，项目关联是可选能力。
- AI 用于理解项目、解释变化、组织功能结构与辅助可视化；真实事实及正式状态不由生成内容替代。
- Human 保留重大决策、最终接受与 Merge Authority；Agent 在后续明确授权的 Task Scope 内实施。

详细边界分别见[架构](architecture.md)和[产品蓝图](product-blueprint.md)，不在本文件复制完整模块功能表。

## 当前授权与非目标

- 当前授权：依据 Human 对 v0.1 共识及文档更新清单的确认，**仅更新与审查项目设计文档**。此授权不包含业务代码、依赖安装、部署、项目自动写入或功能开发。
- 当前不开发：Coding Agent 的直接控制与自动派发、复杂多 Agent 协作、多项目高级管理、完整学习/评分系统、创意管理、重复的代码版本管理系统，以及重复的 Agent 测试/审核/验收引擎。
- 不为追求可视化效果提前建设复杂绘图引擎、任务状态同步系统、持续全量索引或扫描快照历史。
- 约束：本地优先、低耦合、高内聚、最小必要存储、源数据与业务状态分离；不得公开凭证、个人隐私或本地配置，也不得未经授权改写治理规则、共享历史或选择许可证。

产品规划不自动扩大单次 Task Scope；每次业务开发仍需明确目标、范围和验收条件。

## 目前可核验的设计工作成果

- 项目目标、三模块职责、总体架构方向与第一阶段核心价值已有 Human 设计共识。
- 项目文档可通过 Git 版本、实际差异、Markdown 链接和文档间一致性检查进行验证；这不构成运行中的业务能力验证。
- 后续有代码后再针对具体任务定义构建、测试、AI Eval 或其他匹配的 Required Gates；不预先声明不存在的检查为 PASS。

## 待确认事项

- 本地界面形式（桌面或本地 Web）、运行平台、技术栈、数据库和内部接口。
- 本地/GitHub 连接凭证、访问权限、具体同步频率、失败与离线降级方式。
- 版本差异摘要的具体范围、AI 模型提供方、成本与隐私策略。
- 项目功能层级及设计/开发进度的细分状态、证据关联和可视化交互形式。
- 知识资料格式、托管与引用的具体存储策略、检索和 AI 总结质量要求。
- 备份与恢复、许可证、分支保护，以及后续 CI/验证配置。
