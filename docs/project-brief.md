# Project Brief

## 项目身份与目的

- 项目名称：Personal AI Assistant（个人 AI 助手）。
- 目标用户：个人使用者；具体用户画像随真实使用情况逐步完善。
- 长期愿景：建立模块化、本地优先的个人 AI 工作空间，逐步支持项目理解与全景、个人知识库，以及按需独立界面。
- **近期产品定位（v0.2）**：面向个人 AI 辅助软件开发的**项目上下文协同能力**，用可信的本地/Git/GitHub 事实连接云端规划与本地 Coding，帮助现有 AI 客户端理解项目现状、重要变化及信息缺口。
- 近期核心价值：区分正式已合并成果、已推送开发成果及本地未提交工作；优先提供可复用的只读 MCP 工具，不重复建设 Git 客户端、AI 聊天软件或自动文件同步系统。
- 本项目自身也是被管理的项目：需求、架构与产品设计属于正式项目工作，确认后的文档与后续代码一样纳入 Git 版本管理。

## 当前已确认的产品与架构方向

- 采用**本地优先的模块化单体核心**，保留三个业务模块。**插件优先**：首期复用已有 AI 客户端，不把独立 Web/桌面工作台和自建 AI 对话作为开工前提。
- **双工作区**：ChatGPT 项目空间主要用于需求、规划和审查；本地 Codex / DeepSeek Harness 执行授权的 Coding 与验证；GitHub 提供正式已合并成果和已推送 PR 的共同版本基线。云端聊天不是自动同步的 Git 工作区，默认无法看到本地未提交修改。
- **统一核心、分环境接入**：本地项目事实通过独立核心及 MCP 只读工具提供给本地客户端；云端规划优先通过现有 GitHub 访问能力读取已共享成果，不预设公网 MCP 或双向文件同步。Codex 已验证 T01/T03 工具，DeepSeek Harness 已验证复用 T01 工具；T03 在 DSH 中尚未验证。多客户端共享事实不等于共享聊天记录或授权。
- **模块 1：项目接入与上下文管理**，独立接入本地目录或 GitHub 仓库，也可关联；按需提供项目结构、文件、Git 事实及版本变化信息。
- **模块 2：智能项目管理**，以项目目标、模块与功能的全景展示和已有开发信息的只读汇总为产品方向；不复制现有 Agent 的任务执行、测试、审核或验收系统。
- **模块 3：个人知识库**，可独立收藏、管理、检索资料并辅助总结，项目关联是可选能力。
- AI 理解、变化解释与可视化优先复用已有客户端能力；真实事实与正式状态不由生成内容替代。
- 首期技术试行已使用 Python + MCP SDK + 系统 Git CLI 与 Windows 本地 stdio；T01/T03 已通过 Codex 做过真实调用验证，T02 仅验证 DSH 对 T01 工具的接入。这是原型验证，不构成完整客户端支持矩阵、打包方案或长期兼容承诺。暂不引入 FastAPI 或独立 UI。
- Human 保留重大决策、最终接受与 Merge Authority；Agent 在后续明确授权的 Task Scope 内实施。

详细边界分别见[架构](architecture.md)和[产品蓝图](product-blueprint.md)，不在本文件复制完整模块功能表。

## 当前授权与非目标

- 实施授权边界：T01/T03 的只读接入原型已在各自 PR 中授权并合并，T02 为客户端接入验证；这些历史授权不构成后续模块开发的概括性授权。后续任务仍须明确目标、范围、验收条件与必要审批。
- 当前不开发：Coding Agent 的直接控制与自动派发、复杂多 Agent 协作、多项目高级管理、完整学习/评分系统、创意管理、重复的代码版本管理系统，以及重复的 Agent 测试/审核/验收引擎。
- 不为追求可视化效果提前建设复杂绘图引擎、任务状态同步系统、持续全量索引或扫描快照历史；不擅自把本地文件上传云端，也不因 ChatGPT Web 接入假设而提前开放公网 MCP。
- 约束：本地优先、低耦合、高内聚、最小必要存储、源数据与业务状态分离；不得公开凭证、个人隐私或本地配置，也不得未经授权改写治理规则、共享历史或选择许可证。

产品规划不自动扩大单次 Task Scope；每次业务开发仍需明确目标、范围和验收条件。
