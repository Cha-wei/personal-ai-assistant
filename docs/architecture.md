# Architecture

## 目标与约束

项目范围与授权依据见 [Project Brief](project-brief.md)。本文件记录已明确方向，不授权业务实施。

## 当前架构方向

依据 Human 于 2026-10-26 的初始化任务：

- 采用模块化思路，低耦合、高内聚；模块职责与依赖关系须清晰。
- 本地项目接入和 GitHub 仓库接入可独立使用，也允许关联。
- 项目管理与知识库尽可能保持独立。
- 为未来 Coding Agent 接入保留扩展空间；尚未确定扩展机制。

概念职责：模块 1 获取项目结构、文件、版本和变更事实；模块 3 负责项目任务、进展、证据、预核验与人工确认；模块 4 负责资料管理、检索、总结与问答。模块 3 可能消费模块 1 提供的事实，但依赖方式、契约及数据流未决定；知识库不应被假定必须依赖项目接入。

## 尚未决定

- 编程语言、界面形态、框架、核心依赖、运行及部署方式。
- 数据库、文件存储、索引、缓存与数据模型。
- API、模块接口、事件机制、同步方式与权限边界。
- 模型提供方、Agent 协作协议和凭证存储。
- 失败边界、降级、备份与恢复方案。

没有业务实现可作为当前软件架构证据。运行及验证入口见 [README](../README.md#当前验证入口)。

## 重要决策

上述方向来自 Human 初始化任务；没有已批准的具体技术选型。未来重大决策按 [Workflow](../CONTRIBUTING.md) 记录问题、选项、取舍、状态、批准依据、实施授权范围及重访条件；批准后再实施。
