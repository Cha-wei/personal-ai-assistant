# 产品蓝图

## 项目定位与产品价值

个人 AI 助手是模块化、本地优先的个人 AI 工作空间。当前首先解决**真实项目接入、版本变化感知与项目上下文理解**，逐步提供一眼理解项目全貌的可视化体验，并支持独立的个人知识库。

本项目自身的规划、架构文档与后续代码也是正式项目成果；设计进展不应因尚未编码而显示为“没有项目进展”。

## 业务模块与边界

| 模块 | 核心产品能力 | 当前产品定位 |
| --- | --- | --- |
| 1：项目接入与上下文管理 | 本地目录和 GitHub 仓库独立接入或关联；项目结构/文件/Git 事实查询；已观察版本之间的变化感知 | 近期实施重点，默认只读，不重复建设 Git |
| 3：智能项目管理 | 项目目标、模块与功能全景；设计和开发进展展示；复用任务、审核和 GitHub 证据提供只读汇总与提示 | 重要产品体验，分阶段实现，不接管现有 Agent 验收 |
| 4：个人知识库 | PDF、技术资料、网页与视频链接、笔记收藏；基础分类、检索和 AI 总结 | 相对独立的业务模块，允许可选项目关联 |

统一工作空间提供项目入口、基础概览、知识库入口和 AI 对话，不单独承担业务模块的正式状态管理。编号沿用 Human 已确认的规划，不据此推定存在模块 2。

## 模块 1：第一阶段核心体验

- 接入一个本地项目或独立 GitHub 仓库，也能够明确关联二者。
- 按需读取项目目录、文件、当前分支、提交与本地工作区状态；远程仓库可在没有本地克隆时查询。
- 打开项目或主动刷新时，以必要的上次成功观察版本标识为比较基线，识别新观察到的提交或其他可查询差异，显示来源、版本、检查时间。
- 不复制完整代码仓库、不保留每次完整扫描快照、不将 GitHub 推送状态与本地未提交修改混为一谈。
- 远端不可用、权限不足、数据过期或变更范围无法确认时清楚提示，不伪造完整历史。

## 模块 3：项目功能全景与进度信息

模块 3 的产品目标是：用户打开项目，能立即理解**项目做什么、有哪些模块和功能、哪些已完成设计、哪些正在开发及其依据**。这不等于要先开发复杂的绘图引擎或另一套任务管理系统。

### 信息层级及来源

- **项目 → 模块 → 功能 → 相关任务/设计与执行证据**；产品功能层级不同于代码文件夹结构。
- 以现有产品蓝图、项目介绍和架构文档描述功能结构，优先复用仓库内 Markdown 任务/审核记录、GitHub Issues/PR 和测试结果说明实际活动。
- 只做能够明确证实的任务与功能关联；来源冲突、未知和旧数据要标记，不依赖标题相似度自动合并。

### 两个进展维度

- **设计进展**：反映需求、架构和功能设计工作，区分讨论/待确认与经过 Human 确认的设计；设计文件是否已提交到 Git 是另外的版本事实。
- **开发进展**：反映功能实现、测试和人工验收；提交代码、PR 合并或测试通过均不能单独等同于已验收。
- 具体状态枚举、阻塞分类与正式完成率算法尚未确定；第一版不得为了好看的百分比推断未知任务或功能已完成。
- 正式任务和验收状态沿用已有权威记录，AI 分析只提出建议；暂不实施重复的 Agent 测试、审核、验收或任务派发体系。

### 可视化策略

- **基础视图**：稳定显示项目介绍、模块/功能卡片、版本变化与详情入口，确保状态可追溯。
- **AI 辅助理解**：利用模型按需从现有文档提取功能结构、解释变化并组织图表描述，重要推断需与事实区分。
- **可选效果图**：根据使用需要通过模型 API 生成较丰富的项目功能/架构视觉效果；静态生成图不作为正式状态唯一来源，也不替代必要交互。
- 视觉效果的具体形式、模型及成本暂不决定，不让生成式展示阻碍模块 1 的基础可靠性。

## 模块 4：个人知识库

独立支持资料收藏、基础分类、搜索和 AI 辅助总结；支持外部引用和用户主动导入的托管资料。网页和视频初期可只保存链接与元数据。与项目关联属于可选协作，不要求先实现项目管理能力。

## 分阶段产品实现建议

| 阶段 | 主要验证价值 | 边界 |
| --- | --- | --- |
| 1：项目接入最小闭环 | 能接入本地/GitHub，读取真实文件与版本事实 | 不新增版本控制系统 |
| 2：版本变化感知 | 能识别两次成功观察版本间的差异并追溯来源 | 不保存每次扫描或全部代码差异 |
| 3：AI 项目理解与基础概览 | 能解释项目目的、结构和关键版本变化 | 不将 AI 推断作为正式事实 |
| 4：功能全景与已有记录汇总 | 能查看项目模块/功能、设计及开发进展；渐进关联现有证据 | 不接管任务执行或人工验收 |
| 5：知识库与渐进增强 | 收藏、分类、检索、总结；按需要增加提醒或生成式展示 | 知识库可独立推进，阶段不强制串行 |

功能全景图是重要的**产品体验**，但不是第一阶段必须解决的复杂技术问题。首期可以提供简单项目概览，丰富展示逐步增加。以上分期是规划，不自动授予任何业务实施权限。

## 当前正式范围与未来候选

目前已完成 Bootstrap，处于设计与文档版本化阶段；尚无业务代码。已确认的 v0.1 设计方向需要按照现有 [Workflow](../CONTRIBUTING.md) 审核纳入仓库；后续实施另需明确 Task Scope 和验收条件。正式项目约束见 [Project Brief](project-brief.md)，架构原则见 [Architecture](architecture.md)。

暂不开发：Coding Agent 直接控制与自动任务派发、复杂多 Agent 协作、多项目高级管理、完整学习/测验/能力评分体系、创意管理、平行的任务状态系统及重复的开发测试/审核/验收引擎。未来是否开发取决于实际需求，不构成排期承诺。

## 尚待细化

具体界面和交互形式、技术栈、存储、模型服务、权限与同步策略、任务/功能关联字段、状态枚举、图形生成方案和知识库详细验收标准仍需按阶段确定。产品蓝图描述范围与方向，不应被当作已实现功能或一次性实施授权。
