# Task：填写目标

> 可直接用于任务消息、Issue 或 PR，不要求新增任务文档。简单任务用几句话说明即可；已有信息可以引用，不必重复填写。流程以 [CONTRIBUTING](../CONTRIBUTING.md) 为准。

## 必要信息

- 目标与可验证验收条件：说明要解决什么问题、如何判断完成；简单任务可以简短表达。
- 范围与必要的非目标：说明本次要做什么，以及明确不应顺带做什么；不要求为简单任务单独列出冗长清单。
- 当前 Human 授权与限制：引用当前任务或可追溯的明确批准；若授权和限制已经清楚，无需重复。需要时注明只读、仅设计或允许实施。

## Agent 开始前检查（由 Agent 主动完成，不要求 Human 预填）

- 按任务需要检查当前仓库状态、相关规范、项目文档、依赖和输入版本；不必无差别扫描整个仓库或全部历史。
- 判断任务风险与最简适用流程；Human 无需预先选择风险级别。
- 识别会影响范围、授权、安全或验收的阻塞问题。只有这些问题确实阻止安全、正确地继续时才向 Human 澄清；其他未知项应如实标记，并可继续独立且已授权的工作。

## 按需补充（仅在任务确实需要时）

- 方案或重大待决问题：选项、trade-off、建议及批准状态。
- 任务拆分、依赖与实施顺序：仅当任务复杂、跨模块、存在关键依赖或需要协调时填写。
- 输入版本（base branch / SHA）：当版本边界、交接或复现要求重要时填写。
- Write Scope 与唯一 Owner：单人执行可由明确执行者隐含；多执行者或交接时明确。
- 多 Agent：仅在确实并行时列出依赖、隔离方式及整合负责人。
- Validation / Required Gates：按实际改动确定；标准和高风险任务的 Independent Review 是 Required Gate。
- 失败影响与回滚方案：按风险和可逆性填写。

## Checkpoint（仅暂停或交接时）

引用现有记录，补充 branch/head、未提交改动与 ownership、验证版本/结果、剩余工作及下一步。不得用摘要代替仓库恢复，不把旧验证写成新 head PASS。
